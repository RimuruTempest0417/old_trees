# v0.11.5 — 實地考察頁的「預留空間」改為已上線／規劃中兩段

使用者檢查實地考察分頁時發現：頁面下方那張卡標題寫「這一區接下來要放什麼」，把六項**已經做好**的功能
（QR 掃描帶入樹號、與官方巡查比對、列印版考察單等）跟還沒做的混在一起列成待辦 —— 會誤導組員以為功能還沒上線。

## 內容

`public/js/field.js` 的那張卡改成兩段：

**這一區現在就能做的事（已上線）** —— 三項已完成的都附上真的可以點的入口：

| 功能 | 入口 |
| --- | --- |
| 掃描二維碼直接帶入樹號（掃描後開啟該株考察表單，並自動比對樹種、官方樹齡與樹高） | `#/qr?mode=field` |
| 與官方值比對時間序列（《名錄》官方值、自然網歷次快照、實地紀錄接成同一株序列；明顯變化標「需確認」、官方值變動標「官方資料更新」） | `#/monitoring` |
| A4 紙本考察單（可帶入某株基本資料，現場沒有網路也能寫） | `#/card?mode=form` |

**還在規劃中** —— 保留四項真的還沒做的：手機拍照上傳、GPS 誤差半徑與最近古樹比對（一鍵填座標已完成）、
多人協作與審核（需 Supabase Auth）、**觀察項目結構化**（題目要求的樹皮剝落／黴斑／白色鹽類結晶、
鄰近馬路／建築物／排水口／水泥覆蓋範圍，目前寫在「立地環境」與「病蟲害／人為損傷」兩個文字欄）。
