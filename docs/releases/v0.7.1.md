# v0.7.1 — 修「路綫推薦」錯誤 ＋ 胸徑／胸圍改用市政署官方數據

## 一、修正路綫推薦只顯示 `Cannot read properties of null (reading 'name')`

**現象**：線上按「路綫推薦」時，右側詳情只出現一句英文錯誤，路綫五（全澳最老古樹巡禮）完全沒有停靠站。

**根因（只有連上 Supabase 才會發生，本機示範模式測不出來）**：
後端在 Supabase 模式下用資料庫函式 `rpc_scatter` 當「全部古樹」的來源。
那個函式是為了畫樹齡／樹高散佈圖而寫的，只回傳
`(tree_no, age_years, height_m, species, parish, health)` —— **沒有座標**。
路綫推薦的候選點必須有 `lat/lon`，於是每一株都在座標檢查被濾掉，
候選清單變成空的，後端回 `{route: null, stops: [], message: '沒有符合條件的古樹…'}`
（HTTP 200，不是錯誤），前端接著讀 `r.route.name` → 就拋出那句英文。

**修正**：
1. `lib/repo.js` 的 `allTrees()` 改為從 `v_trees` 取資料，並且**明確列出含 `lat`、`lon` 的欄位**
   （不再呼叫 `rpc_scatter`），並加上註解說明原因。
2. 前端補上守門函式 `routeProblem()`：後端回空路綫時顯示「沒有符合條件的古樹，請調整篩選條件。」
   這類可讀訊息，並清空地圖圖層，不再讓畫面炸掉。

**回歸測試**（本機示範模式重現不了這個 bug，所以改用兩種方式守住）：
- `tests/supabase-path.test.js`（新增）：以假的 `fetch` 攔截 PostgREST 請求，直接檢查
  `allTrees()` 送出的查詢欄位必須含 `lat`、`lon`，且不得呼叫 `rpc_scatter`。
  **已驗證：把程式還原成出事前的寫法，這支測試會失敗。**
- `tests/api.test.js`：主題路綫（`oldest-trees`、`macau-heritage-core`）必須真的產生停靠站，且每站都有座標。
- `tests/ui.test.js`：`routeProblem()` 的實際行為（null 路綫／空陣列／正常路綫三種情況）。
- `tests/repo-supabase` 同檔另含「測試前提：確實跑在 Supabase 模式」的自我檢查。

## 二、胸徑／胸圍改用市政署官方數據（不再由胸徑換算）

**背景**：市政署古樹名木的逐株資料本來就有「胸徑(厘米)」「胸圍(厘米)」，平台先前欄位沒接上，
單株詳情是用「胸徑 × π」自己算胸圍。使用者指出官方每株都有值，要求直接採用官方數據。

**官方資料實況**（`oldtrees_c.json`，658 筆）：
- 胸徑 `treeDiameter`、胸圍 `treeSurround`：**658/658 皆有值**（樹 491 鳳凰木＝86.00／270.2，
  與市政署彈窗一致）。
- **290 株是多主幹**，官方欄位是「逗號並列的每支主幹量測值」，例如 #86：
  胸徑 `279.00,260.00,282.00`、胸圍 `876.5,816.8,885.9`（兩個清單逐支一一對應）。

**作法**（不平均、不估算、不換算）：
- 代表值取**胸徑最大的那一支**，胸圍取**同一支主幹**的值（`diameter_cm`／`girth_cm`）。
- 新增 `stem_count`（主幹數）與 `stem_measures`（官方逐支完整量測），介面與紙本都會標示
  「N 支主幹，取最大胸徑那支」並列出逐支數值，資訊不減。
- 前端移除「胸徑 × π」的換算，單株詳情、A4 檔案卡都改顯示官方值並註明「（市政署）」。
- 資料庫新增三個欄位（`girth_cm`、`stem_count`、`stem_measures`），已納入 `schema.sql` 的版本升級段，
  **請依下方指示重跑一次 `init.sql`**。
- 附帶修掉一個小瑕疵：列印卡片原本把內部代碼直接印成「（official）」，現改為「（市政署逐株實測座標）」。

## 四、部署後請做一件事

新版資料表多了 `girth_cm`、`stem_count`、`stem_measures` 三個欄位，**Supabase 需重跑一次初始化**：

1. Supabase → SQL Editor → New query
2. 貼上 `supabase/init.sql` 全文 → `Cmd+A` 全選 → Run
3. 回到網站重新整理，`/api/health` 的「資料庫需要升級」提示會消失，胸徑／胸圍即顯示官方值

（在重跑之前網站仍可正常使用，只是胸徑／胸圍會顯示「—」；平台會提示需要升級。）
