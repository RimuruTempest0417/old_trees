# v1.0.6｜安全掃描（ZAP）判讀與安全標頭強化

起因：2026-09-27 的 ZAP by Checkmarx 2.17.0 **被動掃描**報告（被掃主機 `old-trees-kappa.vercel.app`，
24 個未帶認證的 GET 請求）。共 12 條警示——中風險 3、低風險 1、資訊提示 8，**高風險 0**。

先做憑證盤點：報告會完整記錄請求和回應，因此以程式掃過密碼欄位、JWT、`Bearer`、
`Authorization`、`Cookie`、Supabase 金鑰與私鑰，**全部 0 組**；報告本身不進版控
（`.gitignore` 新增 `*ZAP-Report*.html`）。

## 一、逐條判讀

| 警示 | 次數 | 判定 | 處理 |
| --- | --- | --- | --- |
| Content Security Policy (CSP) Header Not Set | 2 | 真的是問題 | 加上全站 CSP |
| Missing Anti-clickjacking Header | 2 | 真的是問題 | `X-Frame-Options: DENY` ＋ CSP `frame-ancestors 'none'` |
| 跨域配置錯誤（`Access-Control-Allow-Origin: *`） | 5 | 真的是問題 | API 改白名單、靜態檔由設定覆寫 |
| X-Content-Type-Options Header Missing | 5 | 真的是問題（低成本） | 加上 `nosniff` |
| Information Disclosure - Suspicious Comments | 1 | 誤報 | 命中 `vendor/marked.umd.js` 的版本註解；不含憑證，保留原樣 |
| Re-examine Cache-control Directives | 3 | 可接受 | 靜態公開資料本就該快取；API 已是 `no-store`／短 `s-maxage` |
| Retrieved from Cache（`Age`） | 5 | 可接受 | Vercel 邊緣快取的正常現象 |
| Tech Detected：HSTS／KaTeX／Leaflet／PWA／Vercel | 5 | 不是問題 | 技術指紋；HSTS 由 Vercel 提供 |

## 二、改了什麼

- **`vercel.json`**：新增全站安全標頭
  - `Content-Security-Policy`：`default-src 'self'`、`script-src 'self'`（無 `unsafe-inline`／`unsafe-eval`）、
    `style-src 'self' 'unsafe-inline'`（Leaflet／KaTeX／Chart.js 需要）、
    `img-src 'self' data: blob: https://tile.openstreetmap.org https://*.supabase.co`、
    `font-src 'self'`、`connect-src 'self'`、`frame-ancestors 'none'`、`base-uri 'self'`、
    `form-action 'self'`、`object-src 'none'`
  - `X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`、
    `Referrer-Policy: strict-origin-when-cross-origin`、
    `Permissions-Policy: geolocation=(self), camera=(self), microphone=(), payment=(), usb=()`
  - 靜態檔（首頁與 js／css／圖示／manifest）的 `Access-Control-Allow-Origin` 由 `*` 覆寫成本站網域
- **`lib/http.js`、`lib/router.js`**：移除寫死的 `Access-Control-Allow-Origin: *`，改為白名單
  （預設本站兩個網域＋本機開發埠，可用環境變數 `PUBLIC_ORIGINS` 追加）；帶 `Origin` 時加上
  `Vary: Origin`，避免 CDN 把某個來源的 CORS 結果餵給另一個來源
- **配合 `script-src 'self'`**：三處行內 `onclick="location.reload()"` 改成
  `public/index.html`／`public/js/app.js` 的 `data-reload` 事件委派，與 `public/offline.html`
  的純連結（離線頁不載入 JS）

## 三、驗證

- 新增 `tests/security-headers.test.js`（**8 項**）：標頭存在、CSP 不含 `unsafe-eval` 且
  `script-src` 只有 `'self'`、`img-src` 涵蓋實際使用的外部來源且不開放整個 `https:`、
  `Permissions-Policy` 只放行定位與相機、前端沒有行內事件處理器與行內 script、
  後端不得再出現 `ACAO: *`、CORS 白名單三種情境（本站來源回聲／其他來源不回／未帶 `Origin` 不回）
- `tests/api.test.js`、`tests/api-security.test.js` 的 ACAO 斷言改為「未帶 `Origin` 不回標頭」
- `tests/pwa.test.js` 的離線頁斷言改為接受連結形式，並新增「不得有行內事件處理器」
- `npm test`：**29 組、392 項全過**；`npm run check`：95 檔語法全過
- 線上覆核：`curl -D-` 讀回標頭，並以無頭瀏覽器載入線上頁面確認 console 沒有 CSP 違規

## 四、這份報告沒有涵蓋的部分

被動掃描只觀察既有流量、不對正式站送攻擊請求，而且沒有登入，因此看不到需認證的路徑；
報告中 84% 的回應是 4xx（掃描器在試不存在的路徑）。「高風險 0、共 12 條」不等於「站上只有這些問題」。
