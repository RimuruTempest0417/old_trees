# v0.15.0 — GPS 誤差半徑比對（實地考察：站對樹）

實地考察最容易出錯的不是量測，而是**站錯樹**。這一版把「有沒有走到正確的那一株」變成可計算、
可記錄、可事後核對的事——用市政署官方逐株座標當基準，與手機定位比對。

## 一、判定規則（為什麼不能只看距離）

手機定位自己帶著誤差半徑：空曠處可能只有 ±5 公尺，樹蔭下或建築物旁可能是 ±80 公尺。
只看「距離 8 公尺」就說「位置相符」，等於把定位誤差當成判斷力。所以判定同時看距離與精度：

| 情況 | 判定 | 顏色 |
| --- | --- | --- |
| 距離 ≤ 30 公尺、定位精度 ≤ ±50 公尺 | 位置相符 | 綠 |
| 距離 > 30 公尺 | 可能不是這一株（核對樹號與現場立牌） | 紅 |
| 定位精度差於 ±50 公尺 | 距離僅供參考（走到空曠處再測） | 橘 |
| 官方沒有這一株的座標 | 無法比對 | 灰 |

30／50 兩個門檻與球面距離公式寫在 `lib/geo.js`（`GPS_MATCH_RADIUS_M`／`GPS_ACCURACY_LIMIT_M`／
`gpsVerdict()`）與 `public/js/field.js` 兩處。前端不能 import 後端的 `lib/`，這是刻意的複製，
`tests/gps.test.js` 逐項比對兩邊的數值與公式（地球半徑、`asin` 形式），改一邊沒改另一邊會紅燈。

## 二、記錄什麼

按下「用目前位置比對樹木位置」之後：現場座標存 `lat`／`lon`、手機精度存 `gps_accuracy_m`、
算出的距離存 `gps_distance_m`（官方沒有座標時**留空**，不補 0）；紀錄清單多一欄「位置比對」，
CSV 也多「定位精度公尺」「與官方座標距離公尺」兩欄。也可以手動輸入緯度／經度，只要官方座標在，
比對照樣算得出來。

紙本考察單同步留了「現場 GPS 座標」「定位精度（± 公尺）」「與官方座標距離（公尺）」
「位置比對（□ 相符 □ 可能不是這一株）」欄位，現場沒網路時先在紙上寫。

## 三、順手修掉的一個小問題（會讓人誤讀數據）

表單的空欄位送出是空字串 `''`，而紀錄清單原本用 `!= null` 判斷有沒有值——空字串不等於 `null`，
所以「沒有量胸徑」會顯示成「**胸徑 0.0 cm**」。沒量到卻看起來像量到 0，報告引用時會被誤讀。
這一版加了 `cleanNums()`／`hasNum()`：空字串一律當成「沒有量」，存 `null`、顯示「—」。
（實測：只填樹高送出後，紀錄列顯示「高 14.20 m 距 5 m／±8 m」，不再出現假 0。）
