# v0.6.2 — 部署後錯誤訊息可讀化：找出「資料庫結構是舊版」並給出修復步驟

您在部署後的網站上看到的兩個問題，都不是「漏上傳檔案」，而是**資料庫結構仍是舊版**
（少了後來新增的資料表／欄位）加上**錯誤訊息被通用化／顯示成 `[object Object]`**，
以至於完全看不出原因。這一版把「看不見的問題」變成「看得見、而且知道要做什麼」。

## 一、您看到的兩個症狀

| 症狀 | 真正的意思 |
| --- | --- |
| 實地考察頁：「讀取紀錄失敗：伺服器處理請求時發生錯誤，請稍後再試。」 | `/api/field-records` 回 503。舊資料庫沒有 `field_records` 這張表（它是 v0.6.0 才新增的），查詢失敗後被 5xx 規則收斂成一句通用訊息 |
| 地圖頁：「讀取失敗 [object Object]」 | 前端 `esc(err.message || err)` 在 err 是「沒有 message 的物件」時，對物件做字串轉換 → 字面上的 `[object Object]` |

## 二、修正內容

### 1. 後端：資料庫錯誤分類 ＋ 可安全對外顯示的訊息

`lib/repo.js` 新增 `describeDbFailure()`，依 Postgres／PostgREST 錯誤碼分類：

| 錯誤碼 | 分類 | 回應內容 |
| --- | --- | --- |
| 42P01／PGRST205 | 缺資料表 | 503「資料庫結構是舊版：缺少資料表 field_records…」 |
| 42703／PGRST204 | 缺欄位 | 503「…缺少欄位 v_trees.official_no…」 |
| 42883／PGRST202 | 缺函式 | 503「…缺少資料庫函式 rpc_overview…」 |
| 42501 | 權限不足 | 503「請確認使用的是 service_role 金鑰」 |
| fetch failed 等 | 連不上 | 503「請確認 SUPABASE_URL」 |
| 其他 | 一般查詢失敗 | 502 附原始錯誤 |

`lib/http.js` 新增 `publicError()`（`err.public = true`）：**只有這類「使用者必須自己處理」
的 5xx 才會原樣回傳訊息與 `hint`**；其他 5xx 仍只回通用訊息，不洩漏內部細節。
同時新增 `errorText()`，任何被丟出的東西（字串／Error／巢狀物件／非 Error 物件）
都能轉成一句可讀文字，`[object Object]` 不可能再出現。

### 2. `/api/health` 自我檢查資料庫結構

新增逐項探測本專案實際用到的 6 張表／檢視表、3 個 RPC，並回報：

```json
"schema": { "ok": false, "missing": ["資料表 field_records（實地考察）：Could not find the table …"],
            "hint": "請在 Supabase Dashboard → SQL Editor 貼上並執行最新的 supabase/init.sql…" }
```

連線層級的失敗（DNS／權限）會**立即停止後續探測**，健康檢查不會被拖到一分鐘以上。

### 3. 網站開頭直接顯示「資料庫需要升級」

偵測到結構問題時，頁面最上方出現提示橫幅，說明缺什麼、要執行哪個檔案，並可展開查看完整清單。
一切正常時不會出現（已加入無頭瀏覽器守門測試，避免誤報嚇到使用者）。

### 4. 前端錯誤一律經過 `errText()`／`errDetail()`

`public/js/ui.js` 新增兩個函式，`api.js` 的錯誤物件帶上 `status`／`path`／`code`／`hint`，
所以畫面會顯示成：
「無法連線資料庫：TypeError: fetch failed（/api/field-records HTTP 503）請確認 Vercel 環境變數 SUPABASE_URL…」
——**端點、狀態碼、原因、下一步一次講清楚**。

## 三、您要做的（一步就好）

到 Supabase Dashboard → **SQL Editor** → 貼上最新的 `supabase/init.sql` 全文 → **Run**。
檔頭的「版本升級」段會自動補上缺少的欄位、資料表與函式（可重複執行，且不會清掉實地考察紀錄）。

完成後重新整理網站：頁首的「資料庫需要升級」提示會消失，實地考察頁可以正常讀寫。
想確認的話可開 `https://<您的網址>/api/health`，`schema.ok` 應為 `true`、`missing` 為空。
