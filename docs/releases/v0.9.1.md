# v0.9.1 — 修好線上 `/api/priority`：路由載入器漏登記

## 症狀

v0.9.0 上線後，本機一切正常，但線上 `GET /api/priority` 回 **HTTP 500 `FUNCTION_INVOCATION_FAILED`**
（Vercel 自己的錯誤頁，不是本站在處理的錯誤）。其他端點（`/api/trees`、`/api/health`…）都正常。

## 根因

`lib/router.js` 有兩份清單：路由表 `ROUTES`（路徑 → id）與模組載入器 `LOADERS`（id → 動態 import）。
新增 `/api/priority` 時只加了路由表，**忘了在 `LOADERS` 加一行**。

為什麼本機測不出來：`scripts/dev-server.mjs` 不走 `LOADERS`——它自己用檔案路徑 `import()` 取得 handler，
再以 `opts.handler` 傳進 `dispatch()`。線上的唯一入口 `api/[[...route]].js` 沒有這個捷徑，
必須靠 `loadRoute()` 找載入器；找不到就 `未知的路由 id：priority` 往外拋，整個 function 崩掉。
（`LOADERS` 的註解本來就寫著「路徑必須是字面字串，Vercel 打包器才追蹤得到」——
這次漏的是「連那一行都沒有」。）

## 修正

1. `lib/router.js`：補上 `priority: () => import('./routes/priority.js')`。
2. `tests/router.test.js` 新增兩條回歸測試（**已驗證：把修正拿掉時測試會紅**）：
   - 每一個路由 id 都真的要能 `loadRoute()` 成功，且載入器路徑必須是字面字串 `./routes/<id>.js`，
     載入器數量與 `lib/routes/` 檔案數一致。
   - **不傳 `opts.handler`** 直接 `dispatch('/api/priority')`：模擬線上唯一入口的路徑，
     本機若只有 dev-server 的捷徑就會漏掉這種 bug。

## 為什麼測試原本抓不到

`tests/router.test.js` 原本只比對「路由表 ↔ `lib/routes/` 檔案」，沒有檢查 `LOADERS`；
而 `tests/api.test.js` 啟的是自己的伺服器（同樣走 dev-server 的捷徑）。
→ 兩處都補上之後，「新增端點忘了登記載入器」這種錯誤在 `npm test` 就會被擋下來。

## 驗證

- 本機：`node --test tests/router.test.js` 9 項全過；全套 **15 組 225 項全過**；語法 59 個檔案通過。
- 移除修正重跑：兩條新測試皆失敗（`未知的路由 id：priority`），證明測試有效。
- 線上：`/api/health` 回報 `v0.9.1`；`/api/priority` 回 658 株受評、S 級 5 株。
