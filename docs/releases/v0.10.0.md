# v0.10.0 — 分級一律以官方為準、官方名錄每日自動擷取、列印路綫站數修正

這一版回應三件查核，並把發現的問題全部修掉。

## 一、分級：一律以官方為準，本平台不再自訂任何級別

**查核結果**：網站的「分級」欄一直都是市政署名錄的官方值，但 v0.9.0 的優先保育名單
額外自創了 **S／A／B／C 級**，等於本平台自己分了一次級——這已移除。

- 移除 `lib/priority.js` 的 `TIERS`／`tierOf` 與所有 `tier` 欄位；改為 `SCORE_MARKS`／`scoreMark`，
  名稱刻意避開「級」字（「75 分以上」「60–74 分」…），只作為讀長名單的分段。
- 優先保育名單的「健康」、「分級」兩欄改成明確標示 **（官方）**，官方未列級者顯示「官方未列級」。
- 篩選條件由「優先等級 S/A/B/C」改為 **官方分級**（一級／二級／三級／不分級）與 **官方健康狀況**。
- 分頁 KPI 由「S 級／A 級株數」改為「官方列級（一級＋二級）」「官方健康狀況：瀕危」。
- 列印名單移除「等級」欄，加入官方分級與健康狀況，並在封面載明分級政策。
- `lib/routes/meta.js` 與 `lib/routes/overview.js` 原本把官方分級寫成「一級（≥500 年）」等
  自訂年齡級距，已改為只顯示官方名稱，避免看起來像本平台自訂的分級規則。
- API：`GET /api/priority` 的 `tier` 參數改為 `grade`（官方分級，可逗號分隔）與 `health`（官方健康狀況）。

官方名錄的實際分佈（658 株）：一級 1、二級 6、三級 646、不分級 5；
官方健康狀況：健康 215、一般 422、瀕危 21。畫面上的數字與來源檔逐筆一致（測試會驗證）。

**過程中抓到的真 bug**：KPI 卡「官方列級（一級＋二級）」顯示 **16**（正確 **7**）。
`num()` 回傳字串，`num(1) + num(6)` 變成字串相接的 "16"；已改為先把數字相加再格式化，
並加入測試（連註解一起檢查的寫法也一併修正，避免測試被自己的說明文字誤判）。

## 二、官方名錄改為每日自動擷取（以前是人手）

**查核結果**：以前**完全沒有自動化**——`scripts/fetch_iam.py` 要用戶手動跑，
資料庫更要在 Supabase SQL Editor 手動貼 `init.sql`；Vercel 與 GitHub 都沒有任何排程。

新增 `.github/workflows/refresh-official-data.yml`：

1. 每天 04:20（澳門時間）自動重抓市政署名錄（`--no-images`，照片不重抓）。
2. **只比對官方名錄的內容**（`data/iam_trees.json`）；內容沒變就還原痕跡、不做任何提交與部署
   （否則每天都會因為擷取時間不同而產生無意義的提交）。
3. 內容有變時：重建 `supabase/seed.sql`、前端快照、`lib/data-meta.js`，先跑完整測試，
   再提交推送 → Vercel 自動重新部署。
4. 同時開一個 GitHub Issue 提醒「請到 Supabase SQL Editor 重跑 `supabase/init.sql`」，
   因為資料庫那一段仍需要手動執行（本站不保管你的資料庫金鑰）。

新增 `lib/data-meta.js`（由 `scripts/gen-data-meta.mjs` 產生）記錄官方資料履歷：
來源、清單端點、擷取時間、筆數、照片數、內容雜湊。總覽頁的「資料方法說明」現在會顯示
**官方資料擷取時間**與內容雜湊，任何人一眼就能確認資料是不是最新的；
`/api/health`、`/api/meta` 的 `site.data` 也帶同一份資訊。
測試會驗證雜湊與 `data/iam_trees.json` 一致，抓了新資料卻忘了更新履歷就會紅燈。

## 三、列印路綫「（0 站）」修正

**查核結果**：真的算錯——下拉的站數用的是「候選地點數」（`site_count`），
而「路綫五：全澳最老古樹巡禮」的候選地點刻意是空的（停靠點由系統按樹齡自動選出），
所以顯示「（0 站）」，但實際會產生 10 站（同一頁下方的提示寫的正是「封面 ＋ 10 站」）。

- 新增純函式 `routeOptionsHtml()`：下拉一律顯示該路綫自己的停靠上限
  （「最多 10 站」，有候選地點時補上「11 個候選地點」），永遠不可能出現 0 站。
- 產生路綫冊時把該路綫的 `max_stops` 傳進 API，成品站數與下拉文字一致
  （例如路綫四從 10 站變 12 站，與策劃設定一致）。
- 新增測試：下拉不得出現「（0 站）」、名稱必須跳脫、空清單要有合理選項；
  API 測試加驗「每一條精選路綫都有停靠上限」與「不帶 `max_stops` 也生得出停靠點」。
