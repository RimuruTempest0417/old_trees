# v0.13.0 — 實地考察：結構化觀察欄位 ＋ 現場照片上傳

這一版把「到樹下要記錄什麼」從自由文字變成可統計的勾選欄位，並讓手機拍的照片真的存進資料庫旁
的儲存空間。因為實地考察紀錄目前仍是 0 筆，這一版**先把工具補齊**：等出隊時，學生在現場勾的每一格、
拍的每一張照片，都會直接對上作業要求的觀察項目。

## 一、結構化觀察欄位（可統計、可匯出、可對照）

| 欄位 | 型別 | 允許值 |
| --- | --- | --- |
| `bark_conditions` 樹皮狀況 | `text[]` | 剝落／黴斑／白色鹽類結晶／無明顯異常（可多選） |
| `surround_items` 周邊環境 | `text[]` | 鄰近馬路／鄰近建築物／排水口／水泥覆蓋／裸露土壤／其他（可多選） |
| `concrete_cover` 樹穴水泥覆蓋範圍 | `text` | 無／少量（少於三分之一）／約一半／大部分（超過三分之二）／幾乎全部覆蓋 |

- 同一份清單寫在**三處**：前端勾選欄、`lib/repo.js` 常數、`supabase/schema.sql` 的 CHECK 限制條件；
  `tests/field.test.js` 逐項比對三邊，前端送得出的值資料庫一定收得下。
- 違反允許值回 `400` 並列出可接受的値，**不靜默丟掉學生填的內容**；重複值去重，逗號／頓號分隔字串也接受。
- 勾「無明顯異常」時前端自動取消其他樹皮項目（互斥），避免出現「正常又剝落」的矛盾紀錄。
- CSV 匯出新增 `樹皮狀況／周邊環境／水泥覆蓋範圍／照片張數／照片網址` 五欄，報告表格可直接用。

## 二、現場照片：手機拍照 → 前端壓縮 → 上傳 Storage

- 表單新增 `<input type="file" accept="image/*" capture="environment" multiple>`（最多 3 張，手機可直接開相機）。
- 選檔即在瀏覽器用 canvas 壓成**長邊 1280、JPEG 品質 0.72**（手機原圖 3–5 MB，不壓一定失敗），
  可即時看到縮圖、容量與移除按鈕。
- 新增 `POST /api/photo`：伺服器端再驗型別與 3 MB 上限，用 `service_role` 上傳到 Supabase Storage 的
  `field-photos/<日期>/<樹號>-<時間>-<隨機>.jpg`，回公開網址；資料庫只存路徑（`photo_paths`），
  讀取時一併回 `photo_urls`，清單直接顯示縮圖。
- 安全性：只接受 JPEG／PNG／WebP 的 data URL；`../`、絕對路徑、外部網址在驗證層一律濾掉；
  bucket 由 `init.sql` 建立且公開唯讀，寫入一律經伺服器，前端不持有任何金鑰。
- **誠實行為**：示範模式（未連接 Supabase）不上傳，照片只留在這台裝置並在畫面明示；
  本機額度不足時放棄照片、留住紀錄文字並提示先匯出 CSV —— 不會默默失敗、也不假裝上傳成功。
- 若 bucket 不存在（舊資料庫未重跑 `init.sql`）回 `503` 並明說「請重跑 supabase/init.sql」。

## 三、A4 紙本考察單同步（並修回單頁）

紙本考察單加上同一組勾選格與照片黏貼區。第一版把 15 個勾選格放在左欄，A4 立刻從 1 頁變 **3 頁**
（左欄只有 60mm，勾選格被擠成多行）；改為放在右欄並用 `.card-check-inline` 橫向展開後量到
`card-body` 233mm／可用 268mm，PDF 回到 **1 頁**（`form-66`、`form-blank` 都驗過）。

## 四、順手修掉的驗證工具問題

- `scripts/card-pdf.py` 以前只把「缺關鍵字」算失敗，於是印出 `✗ form-66：3 頁（預期 1）` 時
  摘要仍寫「全部通過」——**驗證工具自己說謊比沒有驗證更危險**；現在頁數不符與非 A4 都是硬性失敗，
  並加驗空白考察單（`form-blank`）。
- `scripts/gen_upgrade_sql.py` 現在也能推導**陣列型** CHECK（`<@ array[…]`），且舊資料庫的升級
  只會刪掉陣列裡的非法元素、不會整欄覆蓋；生成出的約束名稱與 `schema.sql` 一致
  （`field_records_bark_conditions_check` 等）。
- `scripts/cdp-check.mjs` 新增 `--eval "<JS>"`：等畫面定案後把 DOM 狀態取回來
  （文字比對看不到 `type`／`capture`／`name` 這些屬性）。

## 六、部署前必做

到 Supabase → SQL Editor **重跑最新的 `supabase/init.sql`**（Cmd+A 全選再 Run）：它會補上三個新欄位與
三個 CHECK，並建立 `field-photos` bucket。不重跑的話，紀錄文字仍能寫入，但照片上傳會回
「儲存空間（field-photos）還不存在」。
