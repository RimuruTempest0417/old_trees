# v0.16.0 — C 後兩項：優先保育行動建議 ＋ 科普數據導讀

這一版把「看得出問題」變成「知道下一步做什麼」，也讓科普文章不再只有文字。

## 一、優先保育行動建議（`#/priority`）

名單回答「哪一株最急」，但拿到名單的人接著要問「那我明天先做什麼」。新增的**建議行動清單**由官方資料
推導，十一條規則寫在 `lib/actions.js`，同一個條件永遠得到同一個建議：

| 建議時程 | 行動 | 株數 | 條件 |
| --- | --- | --- | --- |
| 立即處理 | 排入專家複查與搶救復壯評估 | 21 | 官方健康狀況＝瀕危 |
| 立即處理 | 落枝風險評估、設現場告示並加密巡查 | 1 | 區位風險高且優先分數 ≥ 75 |
| 今年內 | 現場量測冠幅並補登官方缺漏欄位 | 591 | 官方冠幅值缺漏 |
| 今年內 | 樹體支撐、樹穴與立地環境改善評估 | 7 | 樹齡 ≥ 300 年 |
| 今年內 | 檢視法定保護牌、圍欄與解說牌 | 7 | 官方分級一級／二級 |
| 今年內 | 核對《名錄》與官方現行值的差異並註記 | 6 | 官方現行值與名錄不同 |
| 今年內 | 補拍全株照與樹幹特寫 | 1 | 官方照片缺漏 |
| 持續追蹤 | 列入稀有母樹保護與種子採集評估 | 67 | 全澳同種 ≤ 3 株 |
| 持續追蹤 | 納入文化導覽路線與解說點 | 7 | 樹齡 ≥ 300 年且列入名錄 |
| 持續追蹤 | 維持每年至少一次樹體檢查 | 4 | 官方健康「一般」且分數 ≥ 60 |

- 每一條都附**依據**（法規名稱、官方指引或可回溯的本站統計）與**為什麼是這一株**。
- **缺值不補**：官方沒有的欄位會變成「去現場補量／補拍」的建議，不是推估值。
- 名單表新增「建議行動」欄；CSV 匯出兩種（名單含建議、建議清單長格式）；
  「複製摘要」一次帶走名單與建議。
- 列印 `#/card?mode=actions`：第 1 頁行動總表，之後每頁 40 列逐株清單
  （「立即處理」全部列出，其餘行動只列代表株；完整名單在 CSV，紙本不變成幾十頁）。

**定位聲明**：輸出的是巡查與資料整理的優先順序，不是樹木醫學診斷或施工方案；
真正的處置（修剪、支撐、土壤改良）必須由具職權的公共部門與專業人員評估後決定。

## 二、科普數據導讀（`#/knowledge`）

12 篇文章開頭新增「用本站數據讀懂這篇」，共 **38 條**導讀，數字由後端以同一份官方資料即時計算
（`lib/knowledge-guides.js`），官方資料更新時文章不會講出過期數字。

- 每條標示「**官方資料**」或「**本站統計**」，並附站內深連結（例：「657 株有可用的官方照片」→ `#/card`）。
- 缺值不顯示假句子：算不出值就略過，不會出現「— 株」或 `NaN`。
- 沒有官方數據的主題維持寫成缺口（例：2000 年後沒有公開的降雨 pH 年值），不用鄰近地區數字代替。
- 例：〈為什麼要保育古樹〉→「全澳受《古樹名木保護名錄》保護的古樹共 658 株」
  「其中 443 株（67.3%）官方健康狀況不是『健康』」「最老的一株 515 年（#544，海南蒲桃）」。

## 三、順手修掉的真問題（測試照樣全綠的那種）

- **`badge-warn`／`badge-danger` 從來沒有樣式定義**：`monitoring.js`（胸徑／樹高變化、需確認）
  與 `priority.js`（官方分級、區位風險）用了這兩個類別，實際渲染成「沒有顏色的徽章」。
  已改用樣式表真的有的 `badge-bad`／`badge-fair`，並新增掃描所有前端模組的守門測試
  （`tests/ui.test.js`：程式碼用到的每一種 `badge-*` 都必須在 CSS 有定義）。
- `allTrees()` 原本不回傳冠幅、照片、座標精度，行動規則會全部落空（冠幅「缺漏」變成 658 株）——
  已補上欄位；Supabase 分支明確對應 `tree_geo_precision`（樹木座標精度）而不是 `geo_precision`
  （地點精度），兩者同名很容易誤用。
- 修正示範模式下照片可用數的判斷（`photo_count` 在示範資料裡每株都填 1，會蓋掉真正缺照片的那一株）。
