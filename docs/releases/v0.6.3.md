# v0.6.3 — 修復 Supabase 42P16：cannot change name of view column

## 一、這個報錯是什麼

```
ERROR: 42P16: cannot change name of view column "species" to "tree_geo_precision"
HINT:  Use ALTER VIEW ... RENAME COLUMN ... to change name of view column instead.
```

PostgreSQL 的 `CREATE OR REPLACE VIEW` 只能**在既有欄位後面追加**欄位，
**不能改變既有欄位的位置或名稱**。舊版 `v_trees` 的第 10 欄是 `species`，
新版同一位置改成了 `tree_geo_precision`（為避免與樹種欄位混淆而改名），
欄位對不上，於是舊資料庫重跑 `init.sql` 時就停在這裡。

同一個道理也會發生在函式上：函式回傳型別改變時，`CREATE OR REPLACE FUNCTION`
會報 `42P13`，所以這次一併處理。

## 二、修法

`supabase/schema.sql` 的檢視表段落改成**先刪再建**：

```sql
drop view if exists public.v_trees         cascade;
drop view if exists public.v_parish_stats  cascade;
drop view if exists public.v_species_stats cascade;

do $$ ... loop  -- 刪除本專案的 6 個 rpc_* 函式
  execute format('drop function if exists %s cascade', r.sig);
end $$;
```

檢視表與函式都是本檔產生的一次性物件，整體重建最乾淨（`cascade` 會一併處理相依物件，
後面的 `create or replace` 再全部重建）。**不會動到任何資料**，`field_records`（實地考察紀錄）
也完全不受影響。

## 三、新增檔案：`supabase/fix_42P16.sql`

只做「刪除舊檢視表與函式」的單獨修復檔，供除錯時先把問題範圍縮小。

兩種執行方式都可以：

- **A（建議）**：直接重跑最新的 `supabase/init.sql`——已內含這段修復，一份就夠。
- **B**：先跑 `supabase/fix_42P16.sql`，再跑 `supabase/init.sql`。
