# v0.6.7 — 修復線上「單株古樹詳情」404（Vercel 萬用入口只匹配一個路徑段落）

## 一、症狀

網站上點任何一棵樹都跳出：

```
讀取失敗
The page could not be found (/api/tree/543 HTTP 404)
```

值得注意的線索：**同一時間 `/api/health`、`/api/trees` 都正常**（`v0.6.6`、
`schema.ok: true`、658 筆），只有 `/api/tree/<編號>` 壞掉。

## 二、根因

Vercel 的萬用入口 `api/[[...route]].js` **實際上線時只匹配一個路徑段落**：

| 請求 | 段落數 | 線上結果 |
| --- | --- | --- |
| `/api/health` | 1 | 200 ✓ |
| `/api/trees` | 1 | 200 ✓ |
| `/api/tree/544` | 2 | **Vercel 直接回 404，function 完全沒被執行** ✗ |

輸出的 404 是 Vercel 自己的頁面（「The page could not be found」），不是本站 API 的
`{"ok":false,"error":"找不到 API 路由 …"}` —— 這正是判斷「請求沒進到 function」的關鍵。

本機 dev-server 由 `lib/router.js` 直接分派，不受 Vercel 這層限制，所以**本機一直正常**，
這也是它上線才炸掉的原因。

## 三、修正（三層，任一層生效即可）

1. **前端改用單段落端點**：`public/js/api.js` 的單株詳情由 `/api/tree/544`
   改為 `/api/tree?no=544`。
2. **路由層同時支援兩種形式**：`lib/router.js` 的 `matchRoute(pathname, search)`
   新增「單段落 ＋ 查詢參數」比對（路由表加 `queryParam: 'no'`）；
   `lib/routes/tree.js` 依序讀 `tree_no`／`no`／URL 末段。
3. **`vercel.json` 加 rewrite**：`/api/tree/:no` → `/api/tree?no=:no`，
   讓 REST 形式（文件與外部引用）在線上也能運作。

## 四、防止再犯的守門測試（`tests/router.test.js`）

- **前端不得出現多段落呼叫**：解析 `public/js/api.js` 的每個 `request('/…')` 路徑，
  只要含第二個 `/` 就失敗。實測：故意加一行 `request('/tree/66')` → 測試立刻紅燈。
- **`vercel.json` 必須有** `/api/tree/:no` → `/api/tree?no=:no` 的 rewrite。
- `tests/api.test.js` 新增：`/api/tree?no=X` 與 `/api/tree/X` 回傳的單株資料必須完全相同，
  且不存在的編號回 404、非法輸入回 400。

## 五、另外發現：網站被 Vercel 登入保護擋住

測試時連正式網址都會 302 轉到 `vercel.com/sso-api`，代表專案開了
**Vercel Authentication（Deployment Protection）**——老師、同學沒有 Vercel 帳號就開不了。
請到 Vercel → 專案 → **Settings → Deployment Protection**，把 Vercel Authentication
設為 `Disabled`（或 `Standard Protection` 只保護預覽環境）。

## 六、驗證

- `npm run check`：44 個檔案語法全過。
- `npm test`：**10 組、137 項全過**（router 4→7、api 12→13）。
- 本機實測：`/api/tree?no=<編號>` 與 `/api/tree/<編號>` 均 200 且資料一致。
- `/api/health` 的 `version` 現為 `v0.6.7`，重新整理頁面即可確認線上已更新。
