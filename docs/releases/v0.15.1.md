# v0.15.1 — 健康檢查會提前抓到「資料庫還沒升級」

v0.15.0 為實地考察新增了 `gps_accuracy_m`／`gps_distance_m` 兩個欄位。原本的健康檢查
（`/api/health` 的 `schema.missing`）只探測 `id,tree_no,observer,health`，因此**資料庫還沒升級時
不會有任何提示**——學生要走到樹下、填完表單、按下儲存才會看到「缺少欄位 gps_accuracy_m」。
實地考察沒有那個時間成本可以浪費。

## 改動

- `lib/repo.js` 的 `SCHEMA_PROBES`：`field_records` 的探測欄位改成**涵蓋前端會寫入的所有欄位**
  （`bark_conditions`、`surround_items`、`concrete_cover`、`photo_paths`、`gps_accuracy_m`、`gps_distance_m`）。
- 新增測試：`tests/gps.test.js` 檢查探測清單必須包含上述欄位（以後再加欄位忘了加探測就會紅燈）。
- `API_VERSION` → `v0.15.1`；`sw.js` 重新產生。

## 效果

還沒重跑 `supabase/init.sql` 時：

- `/api/health` 的 `schema.missing` 會列出缺少的欄位，並附上「請貼上並執行最新的 `supabase/init.sql`」提示；
- 網站頁首出現「資料庫需要升級」橫幅，不必等到儲存失敗才知道。

重跑 `init.sql` 後（欄位補齊）橫幅與 `missing` 都會自動消失。

## 驗證

- `npm test`：**22 組、320 項全過**（`tests/sql.test.js` 以 PGlite 實跑全部探測查詢，確認新探測項
  在全新資料庫上真的可執行；`tests/diagnostics.test.js` 18 項）。
- `npm run check` 全過；`sw.js` 60 項（v0.15.1）。
- 線上 `/api/health` 回 `v0.15.1`；在使用者重跑 `init.sql` 之前，`schema.missing` 會如預期列出
  缺少的 `field_records` 欄位。
