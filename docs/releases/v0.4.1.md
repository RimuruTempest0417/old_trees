# v0.4.1 — 官方照片破圖修正、說明文字更正

接續 v0.4.0 的官方資料整合，逐項檢查後修掉兩個實際缺陷。

## 🐞 修正

### 1. 樹木 471 的官方照片是 HTML 假檔（會出現破圖）

- **症狀**：`public/photos/trees/471.jpg` 在網頁上變成破圖。
- **根因**：市政署網站的官方清單中，樹木 471（假柿木薑子，T0000462）指向的影像檔 `/OldTreesOnline/2787568.jpg`
  已被移除；該站對不存在的影像檔**回傳 HTTP 200 ＋ SPA 首頁 HTML**，抓取程式只檢查 HTTP 狀態就把 HTML 存成 `.jpg`。
- **修正**：
  - `scripts/fetch_iam.py` 新增 JPEG 檔頭驗證（`FF D8 FF`）：下載後立即驗證，非 JPEG 一律刪除並記為抓取失敗。
  - 每次執行都會先掃描既有檔案，清除先前存下的假 JPEG。
  - 新增 `photo_ok` 標記與 `iam_meta.json` 的 `photos_missing` 清單；沒有照片的樹不再輸出 `photo_url`／`photo_source`，前端自動改用樹種相片，**不會出現無照片卻標著出處的矛盾**。
- **實測結果**：清除 1 張假檔、重抓失敗 1 株；有效官方照片 657/658，`photos_missing = ["471"]`。

### 2. 無頭驗證用的資料快照與說明文字未同步

- 總覽頁「資料方法說明」、頁尾「資料來源」與「使用提醒」、科普 FAQ 仍寫著座標是 OpenStreetMap Nominatim 地理編碼的**研究用近似值**；
  v0.4.0 起座標已全面改採市政署逐株座標，文字與事實不符。已於 `public/js/dashboard.js`、`public/index.html`、
  `scripts/content.py`（同步更新 `data/conservation.json`）更正，並改為連到市政署專頁。

## 🧪 測試強化

- `tests/iam.test.js` 的破圖測試由「檔案存在」升級為**逐張驗證 JPEG 檔頭**，並檢查
  「沒有照片的樹必須等於 `photos_missing`」、「目錄不得有孤兒檔」——這個測試若早先就寫成驗證檔頭，v0.4.0 上線時就會擋下破圖。
