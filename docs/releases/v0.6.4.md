# v0.6.4 — 修復 Supabase 23514：check constraint「sites_geo_precision_check」

## 一、這個報錯是什麼

```
ERROR: 23514: new row for relation "sites" violates check constraint "sites_geo_precision_check"
DETAIL: Failing row contains (1, 氹仔區兵房斜巷6號, …, official, iam, /photos/sites/001.jpg, …)
```

問題出在**限制條件的「允許值」**：舊版 `sites.geo_precision` 只允許 `('exact','approx','parish')`，
新版加入了 `'official'`（市政署逐株座標）。舊資料庫上的限制條件還是舊的那條，
所以 seed 一寫入 `'official'` 就被擋下來。

## 二、為什麼上一版沒修好（我的疏漏）

v0.6.1 的升級段落邏輯是「**限制條件不存在時才新增**」：

```sql
if not exists (select 1 from pg_constraint where conname = 'sites_geo_precision_check') then
  alter table public.sites add constraint ... ;
end if;
```

舊資料庫上這條限制條件**是存在的**（只是定義過時），所以這段永遠不會執行，
問題就一直留著。正確做法是**一律先移除再重建**。

## 三、修法

升級段落現在對本專案定義的三個 CHECK 條件一律「先刪再建」，並在重建前把超出新允許值的
既有資料正規化（否則 `add constraint` 會因為舊資料而失敗）：

```sql
do $$ begin
  if to_regclass('public.sites') is not null then
    update public.sites set geo_precision = 'approx'
      where geo_precision is not null and geo_precision not in ('official','exact','approx','parish');
    alter table public.sites drop constraint if exists sites_geo_precision_check;
    alter table public.sites add constraint sites_geo_precision_check
      check (geo_precision in ('official','exact','approx','parish'));
  end if;
  -- trees.grade、trees.health 同樣處理
end $$;
```

`to_regclass` 守衛讓同一段在全新資料庫（表還沒建立）時直接跳過，因此仍然可重複執行、順序無關。

   `new row for relation "sites" violates check constraint "sites_geo_precision_check"`。
3. **修正後**：重跑 schema ＋ seed 成功，`geo_precision = 'official'` 的官方座標資料正常寫入，

   升級時先正規化為 `approx`，再重建限制條件，成功。
